Mastering Bitcoin · Section 7 — the little programs that lock coins

1 / 7

Every coin is locked by a programConcept

An output carries a locking script (the condition to spend). To spend, you supply an unlocking script. Combined and run, they must leave a single 'true' on the stack.

2 / 7

Script runs on a stackStack

Script is stack-based. Data values are pushed; opcodes pop and push. 2 3 OP_ADD leaves 5.

Common: OP_DUP, OP_ADD/OP_SUB, OP_EQUAL, OP_HASH160, OP_CHECKSIG.
3 / 7

Deliberately limitedNo loops

Script has no loops and is not Turing-complete — every script finishes quickly, so no one can freeze the network with an infinite program.
4 / 7

Multisig, P2SH, OP_RETURNPatterns

  • Multisignature (m-of-n): needs m valid signatures from n listed keys.
  • P2SH: pay to the hash of a redeem script; the spender reveals it later.
  • OP_RETURN (0x6a): unspendable output carrying up to 80 bytes of data.

Coding exercisesPractice

  1. eval_script(tokens) — a tiny stack machine.
  2. check_multisig(keys, sigs, m) — m-of-n validation.
  3. op_return_script(data) — build an OP_RETURN output.
