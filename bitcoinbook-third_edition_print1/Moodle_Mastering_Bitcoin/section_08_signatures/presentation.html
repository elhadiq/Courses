What a signature provesGuarantees

  • Authentication — only the private-key holder could make it.
  • Integrity — the signed transaction cannot be altered.
  • Non-repudiation — the signer cannot deny it.
All without revealing the private key.

Signing and verifyingMechanism

ECDSA and SchnorrSchemes

Bitcoin uses ECDSA and, since Taproot (2021), Schnorr — simpler, provably secure, and combinable. Both use secp256k1.

Never reuse the random nonce. Signing two messages with the same nonce lets anyone recover your private key.

What the signature coversSIGHASH

FlagValueCommits to
SIGHASH_ALL0x01all inputs and outputs
SIGHASH_NONE0x02inputs, no outputs
SIGHASH_SINGLE0x03inputs + matching output
ANYONECANPAY0x80modifier: only this input

So 0x83 = SINGLE + ANYONECANPAY.

DER and the low-S ruleEncoding

A signature is a pair (r, s) in DER form, starting with byte 0x30. Since (r, n−s) is also valid, Bitcoin accepts only low-S:

accepted only if s ≤ n / 2
