Bitcoin Security

Bitcoin's protocol is famously hard to break — but users lose coins to simpler mistakes. This section covers the security principles and habits that actually keep funds safe.

What you will be able to do

  • State the core security principle: control of keys is control of coins.
  • Explain why an address checksum protects users, and verify one.
  • Reason about entropy — what makes a secret hard to guess.
  • Use multisignature and backups to remove single points of failure.

1. The core principle

Everything in Bitcoin security reduces to one sentence: whoever controls the private keys controls the coins. There is no support line, no chargeback, no password reset. This is empowering and unforgiving in equal measure. Security, then, is mostly about two risks: losing your keys (and locking yourself out) and leaking your keys (and letting a thief in). Good practice defends against both at once.

Golden rule. Never type your recovery phrase into a website or app that asks for it, never photograph it, never store it in the cloud. Write it on paper (or steel) and keep it physically safe. Almost every theft of an individual's coins traces back to a leaked phrase.

2. Preventing costly typos: address checksums

A payment to a mistyped address is usually unrecoverable, so Bitcoin addresses carry a built-in checksum (recall Base58Check, Section 4). The last four bytes of the data are the first four bytes of its double-SHA256. When you paste an address, the wallet re-computes that checksum; if it does not match, the address is rejected before any coins move. A single wrong character changes the hash and fails the check.

valid ⇔ SHA256(SHA256(payload))[:4] == checksum_bytes

3. Entropy: what makes a secret unguessable

A secret is only as strong as it is unpredictable. We measure that unpredictability in bits of entropy. If a secret is drawn from a pool of P equally-likely symbols and is L symbols long, its entropy is:

entropy_bits = L × log₂(P)

Each extra bit doubles the number of guesses an attacker needs. A 12-word BIP39 phrase draws 12 words from a 2,048-word list, giving about 12 × 11 = 132 bits — far beyond any brute-force attack. Compare that with an 8-character password from the 26 lowercase letters: only about 38 bits, crackable in moments. This is why wallets use generated phrases, not human-chosen passwords, to protect keys.

4. Removing single points of failure

Storing everything in one place means one accident (or one thief) is catastrophic. Two techniques spread the risk:

  • Multisignature (Section 7). An m-of-n setup requires several keys to spend. A 2-of-3 kept in three locations means a thief who finds one key gets nothing, and you can lose one key and still recover. In general, an m-of-n tolerates losing up to n − m keys.
  • Cold storage. Keep the keys that guard savings on a device that never touches the internet (a hardware wallet or an offline computer), so malware cannot reach them. Keep only small “spending money” on an online (hot) wallet.

The diagram shows a 2-of-3 setup with keys kept in three separate places. Any two can sign a spend, so a thief who compromises one location gets nothing, and you can lose one key entirely and still recover.

Balance the two risks. More copies of a backup reduce loss risk but increase theft risk; more secrecy does the opposite. A 2-of-3 multisig is popular precisely because it improves both at once.
