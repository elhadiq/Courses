Why Vyper?Security

  • ~$2B stolen via contract bugs in 2023 alone.
  • Vyper (Python-inspired) optimizes for auditability.
  • Strategy: leave out features that hide behaviour.
Goal: make misleading or unsafe code virtually impossible to write.

DecoratorsFunction tags

DecoratorMeaning
@external / @internalCallable outside / inside
@viewReads, cannot change state
@pureCannot even read state
@payableMay receive ether
@nonreentrantLocks against reentrancy
Exactly one of @external/@internal. Never @payable AND @view (receiving value is a state change).

Explicit conversionsSafe

small: uint8 = 42 large: uint256 = convert(small, uint256) # safe upcast back: uint8 = convert(large, uint8) # reverts if too big
Every conversion is written out and bounds-checked — no silent truncation.
5 / 7

Overflow protectionBuilt in

Arithmetic throws on overflow/underflow; clamps enforce bounds on load, pass, and assign.

safe_add(1, 2) on uint8 → 3 safe_add(200, 100) on uint8 → reverts (300 > 255)
A 2018 ERC-20 overflow minted an astronomical balance — this is the class of bug Vyper blocks by default.
6 / 7

Recap

Vyper trades power for auditability: no modifiers, inheritance, inline assembly, or overloading. Every function carries exactly one of @external/@internal, and @payable cannot be @view. Conversions are explicit and bounds-checked, and arithmetic reverts on overflow by default.
