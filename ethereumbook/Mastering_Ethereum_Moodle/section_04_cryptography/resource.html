Cryptography

By the end of this lesson you will understand private and public keys, one-way functions, cryptographic hashes, and exactly how an Ethereum address — with its ERC-55 checksum — is built.

What you will be able to do

  • Explain why a private key is just a very large random number, and why it must stay secret.
  • Describe elliptic-curve multiplication as a one-way function linking private and public keys.
  • State the key properties of a cryptographic hash function.
  • Derive an Ethereum address from a public-key hash, and apply the ERC-55 capitalization checksum.

1. Private keys: just a big random number

A private key is simply a number picked at random. Whoever holds it controls every fund and contract tied to the matching address, so it must stay secret and must be backed up — lose it and the funds are gone forever.

How big a number? A private key is essentially any value between 1 and just under 2256 — a 78-digit number, about 1.158 × 1077. To picture that scale: the visible universe holds roughly 1080 atoms, so there are almost enough Ethereum keys to give every atom in the universe its own account. That is why a randomly chosen key can never realistically be guessed. The one rule: use a cryptographically secure random source, never a simple rand().

A private key, in hex (64 hex digits = 256 bits)

f8f8a2f43c8376ccb0871305060d7b27b0554d2cc72bccf41b2705608452f315

2. Public keys and one-way functions

From the private key we compute a public key using elliptic-curve multiplication: K = k × G, where k is the private key, G is a fixed generator point, and K is the resulting public key (a point, i.e. two coordinates). Ethereum uses the same curve as Bitcoin, called secp256k1.

The crucial property is that this is a one-way function: going forward (private → public) is easy, but going backward (public → private) would require solving the “discrete logarithm problem,” which is computationally impossible. So you can publish your public key to the whole world knowing no one can reverse it to find your private key. That asymmetry is the foundation of every digital signature that proves ownership on Ethereum.

3. Cryptographic hash functions

A hash function maps input data of any size to a fixed-size output called the hash. Cryptographic hash functions add special properties that make them, in Bruce Schneier's words, “the workhorses of modern cryptography”:

PropertyWhat it means
DeterminismThe same input always gives the same hash.
VerifiabilityComputing a hash is fast.
NoncorrelationChanging one bit of input changes the hash beyond recognition.
IrreversibilityYou cannot recover the input from the hash.
Collision protectionTwo different inputs producing the same hash is infeasible.

Ethereum's hash function is Keccak-256. It was the winner of the SHA-3 competition, but Ethereum adopted the original Keccak rather than the later NIST-tweaked FIPS-202 SHA-3, so the two produce different outputs. You can tell them apart with a test vector on the empty input:

Keccak256("") = c5d2460186f7233c927e7db2dcc703c0e500b653ca82273b7bfad8045d85a470
SHA3("")     = a7ffc6f8bf1ed76651c14756a061d662f580ff4de43b49fa82d80a4b80f8434a

The exercises use Python's built-in SHA-256 (from hashlib) to feel these properties directly — it is a different function from Keccak-256, but it demonstrates determinism, fixed length, and the avalanche effect just as well.

4. From public key to Ethereum address

An Ethereum address is derived from the public key in two steps. First, hash the public key with Keccak-256. Second, keep only the last 20 bytes (the 40 rightmost hex characters) of that hash. That is your address, usually written with a 0x prefix:

Keccak256(K) = 2a5bc342ed616b5ba5732269001d3f1ef827552ae1114027bd3ecf1f086ba0f9
last 20 bytes → address = 0x001d3f1ef827552ae1114027bd3ecf1f086ba0f9

5. The ERC-55 checksum

Raw hex addresses have no built-in protection against typos. ERC-55 adds a checksum by cleverly reusing the capitalization of the letters a–f. Because addresses are case-insensitive, the pattern of upper- and lowercase letters can carry error-detecting information without changing the address's meaning. Wallets that understand it can catch a mistyped address with 99.986% accuracy.

The rule is precise. Take the Keccak-256 hash of the lowercase address (without 0x). Then walk through the address character by character: for each letter, look at the hash digit in the same position — if that hash digit is 8 or greater, capitalize the letter; otherwise leave it lowercase. Digits (0–9) never change.

address: 001d3f1ef827552ae1114027bd3ecf1f086ba0f9
hash    : 23a69c1653e4ebbb619b0b2cb8a9bad49892a8b9...
result  : 001d3F1ef827552Ae1114027BD3ECF1f086bA0F9

The letter d (position 4) faces hash digit 6 — below 8, so it stays lowercase. The next letter f faces hash digit c — that is 12, at or above 8, so it becomes F. Change even one character of the address and its hash changes completely, so the capitalization pattern no longer matches and the error is caught. Implementing this rule is the capstone exercise for this section.

Check your understanding

  1. Why can you safely publish your public key? (Answer: deriving the private key from it is infeasible — a one-way function.)
  2. How many bytes of the public-key hash form the address? (Answer: the last 20 bytes.)
  3. In ERC-55, when is a letter capitalized? (Answer: when the hash digit in the same position is 8 or greater.)
  4. Does Keccak-256 give the same output as FIPS-202 SHA-3? (Answer: no.)
