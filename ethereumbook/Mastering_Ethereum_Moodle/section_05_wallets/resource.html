Section 5 · Reading

Wallets

By the end of this lesson you will understand why modern wallets derive every key from a single seed, how a mnemonic backs up that seed, and how a BIP-44 path names any key in the tree.

What you will be able to do

  • Contrast a nondeterministic (random) wallet with a deterministic (seeded) one.
  • Explain how a BIP-39 mnemonic encodes the seed and why words beat raw hex.
  • Describe the HD (hierarchical deterministic) tree and read a key path.
  • Build and interpret a BIP-44 derivation path, including hardened indices.

1. Random wallets vs seeded wallets

The very first Ethereum wallets were nondeterministic: each new address meant a brand-new, unrelated random private key. Good privacy practice is to use a fresh address often, so these wallets keep growing a pile of unrelated keys — and every one of them must be backed up. Miss a backup before your disk dies and those funds are gone. (Clients like Geth still store such a key in an encrypted keystore JSON file, stretched with a slow key-derivation function so a stolen file resists brute force.)

A deterministic or “seeded” wallet fixes this. Every private key is derived mathematically from one master number called the seed. Because the seed alone can regenerate every key, a single backup taken once, at creation, secures the whole wallet forever — and lets you move all your keys between wallet apps by transferring just the seed.

2. Hierarchical deterministic (HD) wallets

The leading form of seeded wallet is the hierarchical deterministic (HD) wallet from Bitcoin's BIP-32 standard. Its keys form a tree: a parent key derives child keys, each child derives grandchildren, and so on. The tree lets you give branches meaning (one branch for receiving, another per department in a company), and — remarkably — you can derive a whole branch of public keys from a parent public key without ever touching the private keys. That makes it safe to run a receive-only server that can generate endless addresses but cannot spend a cent.

3. Mnemonic backups (BIP-39)

A seed written as raw hexadecimal is dangerously easy to mistype. BIP-39 instead encodes the seed as an ordered list of common words — a mnemonic:

FCCF1AB3329FD5DA3DA9577511F8F137 ← the seed in hex

wolf juice proud gown wool unfair wall cliff insect more detail hub

Words are far easier to transcribe on paper and to error-check: if you wrote down inzect, recovery software would immediately see it is not a real word and suggest insect. The wallet shows you 12–24 words when it is created; that list is your backup. Crucially, the wallet chooses the words randomly — a mnemonic is not a “brainwallet” of words you invent, because humans are terrible sources of randomness. The mnemonic must stay private, so back it up with pen and paper, not a digital file.

4. Paths and hardened keys

Keys in the tree are named by a path separated by slashes. Private keys start from m, public keys from M. So m/0 is the first child private key, and m/0/1 is the second grandchild of that first child.

Each level uses a 32-bit index, split into two halves. Indices from 0 to 231−1 are normal; indices from 231 up to 232−1 are hardened. Hardened derivation breaks the mathematical link that would let a leaked child key expose its parent, so it is used as a firewall near the top of the tree. Hardened indices are shown with a prime mark counting from zero: index 231 displays as 0', index 231+1 as 1', and so on.

BIP-44 fixes a standard five-level shape so wallets interoperate:

m / purpose' / coin_type' / account' / change / address_index

purpose is always 44'; Ethereum's coin_type is 60'; change is 0 for receiving. So the third receiving address of the first Ethereum account is M/44'/60'/0'/0/2.

Building that path string and telling hardened from normal indices are exactly what the exercises ask you to do.

Check your understanding

  1. Why does a seeded wallet need only one backup? (Answer: the seed regenerates every key.)
  2. Why prefer a mnemonic over raw hex? (Answer: words are easy to transcribe and error-check.)
  3. Is index 231 normal or hardened? (Answer: hardened, displayed 0'.)
  4. What is the BIP-44 coin_type for Ethereum? (Answer: 60'.)

Practice. Three Python exercises: (1) build a BIP-44 path string from its components, (2) decide whether an index is hardened, and (3) format an index the way wallets display it (with a prime mark for hardened keys).
