Practical DevOps

A hands-on course that starts from a bare terminal and ends with a real application built, tested, containerised, deployed to Kubernetes and monitored — all by pipelines you wrote yourself. Everything runs on your own laptop. No cloud account, no credit card.

What DevOps actually is DevOps is not a tool and not a job title you buy. It is the practice of shortening the distance between "a developer changed a line of code" and "that change is safely running in production." Every tool in this course exists to remove one manual step from that path.

How this course works

Each module follows the same rhythm, deliberately:

SectionWhat it does
Why it existsThe concrete pain this tool solves. You never learn a tool before you feel the problem.
Core conceptsThe 5–10 ideas you actually need. No exhaustive reference dumps.
LabCommands you type. Real output. It breaks in places on purpose, and you fix it.
ExercisesUnguided tasks. Solutions are collapsed — try first.
CheckpointA short quiz + a checklist of what you should now be able to do unaided.

One idea per page. Each module is split into short pages — one per topic, lab step or exercise set. Open a module to see its contents, then move with Next / Previous at the bottom of each page; the sidebar always shows where you are in the module. Next also carries you across module boundaries, so you can read the whole course front to back without returning here.

The running example. From Module 3 onward you work on one small app — urlshort, a URL shortener in Python with a Redis backend. It stays with you through containers, pipelines, infrastructure code, Kubernetes and dashboards. That continuity is the point: DevOps is about a system, not a set of unrelated tools.

Before you start: setup

You need a machine with at least 8 GB RAM and 20 GB free disk. Linux or macOS natively; on Windows use WSL2 with Ubuntu — every command in this course assumes a Linux shell.

Windows only: install WSL2 first

# In PowerShell, as Administrator:
wsl --install -d Ubuntu
# Reboot, then open "Ubuntu" from the Start menu.
# From now on, every command in this course goes in that Ubuntu shell.

The capstone

After Module 7 you should be able to do the following from an empty directory, without notes. This is the real exit test of the course:

  • Initialise a Git repo with a sane branch strategy and a protected main.
  • Diagnose a connection failure down the layers — DNS, then host, then port, then HTTP — and say whether "refused" or "timed out" points at the service or at a firewall.
  • Write a multi-stage Dockerfile that produces an image under 150 MB running as a non-root user.
  • Compose the app with Redis, with a healthcheck and a named volume that survives restarts.
  • Write a GitHub Actions workflow: lint → test → build → push to GHCR, gated on the tests passing.
  • Define the target environment in Terraform and configure it with an idempotent Ansible playbook.
  • Write Kubernetes manifests with liveness/readiness probes, resource limits, a ConfigMap and a Secret; perform a rolling update and then a rollback.
  • Expose /metrics, scrape it with Prometheus, chart p95 latency and error rate in Grafana, and write one alert rule that fires on a symptom your users would feel.

Do not skip modules. Each one assumes the artefacts built in the previous one.

A note on how to study this

Type the commands. Do not copy-paste the whole lab in one go — the errors are where the learning is, and you cannot debug a pipeline you never saw fail. When something breaks, read the error message completely before searching for it. That single habit is most of what separates people who are comfortable with this stack from people who are not.
