2.12 The troubleshooting toolkit

QuestionCommand
What are my addresses and routes?ip addr, ip route get 1.1.1.1
Is the host reachable at all?ping -c3 <host> (ICMP is often blocked — a failure is not proof)
Does the name resolve?dig +short <host>, getent hosts <host>
Is the port open from here?nc -vz <host> <port>
What is listening locally?ss -tulpn
Where does traffic get lost?traceroute <host> / mtr <host>
What is actually on the wire?sudo tcpdump -i any -n port 6379
Does the whole HTTP request work?curl -v <url>
Work up the layers, not randomly Resolve the name (DNS) → reach the host (IP) → reach the port (TCP) → get a valid response (HTTP). Each step tells you whether to keep going or stop and fix. Jumping straight to reading application logs when the name does not even resolve is how an afternoon disappears.
