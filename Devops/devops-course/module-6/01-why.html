6.1 What Kubernetes is for (and when not to)

Kubernetes solves a specific set of problems that appear once you run containers seriously:

  • Self-healing — a container crashes or a node dies; replacements start elsewhere automatically.
  • Scaling — go from 2 to 20 replicas with one field, manually or on a metric.
  • Zero-downtime releases — rolling updates with automatic rollback when the new version fails to become healthy.
  • Service discovery and load balancing — stable names in front of ephemeral pods.
  • Declarative configuration — the cluster continuously works to make reality match your YAML.
When not to use it Kubernetes has a real operational cost: control plane upgrades, networking, RBAC, storage classes, and a learning curve for everyone on the team. For a single app on a single server with modest traffic, Compose plus a good deployment script is often the better engineering decision. Choose Kubernetes when you have multiple services, need resilience across machines, or a platform team to own it — not because it is on job listings.
