5.6 State — the concept that trips everyone

Terraform records what it created in terraform.tfstate: a mapping from your resource addresses to real object IDs. Without it, Terraform cannot tell "this container does not exist yet" from "this container exists and I made it".

Three rules about state
  • Never commit it. It contains resource attributes including, frequently, secrets in plaintext. terraform.tfstate* and .terraform/ go in .gitignore.
  • Never hand-edit it. Use terraform state mv / rm / import.
  • For teams, use a remote backend with locking (S3 + DynamoDB, Terraform Cloud, GCS). Two concurrent applies against local state corrupt it and can duplicate or orphan real infrastructure.

The three commands that rescue you

# someone created a resource by hand; adopt it into state
terraform import docker_container.api <container-id>

# stop managing something without destroying it
terraform state rm docker_container.api

# see what Terraform thinks exists
terraform state list
terraform state show docker_container.redis
