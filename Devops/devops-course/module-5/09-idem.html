5.9 Idempotency, concretely

Run a playbook twice. The second run should report changed=0. If it does not, some task is doing work unconditionally, and you cannot trust the report to tell you what actually changed.

PLAY RECAP
web1 : ok=6  changed=4  unreachable=0  failed=0    # first run
web1 : ok=6  changed=0  unreachable=0  failed=0    # second run — correct
The command module is the usual culprit command and shell always report changed, because Ansible cannot know what your command did. Prefer a real module when one exists; when you must shell out, guard it: 
- name: Initialise the database once
  ansible.builtin.command: /srv/app/init-db.sh
  args:
    creates: /srv/app/.db-initialised   # skip if this file exists
creates/removes, or register + when, or changed_when — these turn an imperative escape hatch back into something idempotent.
