5.1 The problem: snowflake servers and drift

A server is set up by hand in 2023. Someone patches a config in 2024 during an outage. Someone else installs a debugging tool and forgets to remove it. By 2026 nobody knows what is on that machine, and nobody dares rebuild it because it cannot be reproduced. That is a snowflake: unique, fragile, and impossible to replace.

Configuration drift is how you get there — the slow, invisible divergence between what you think is deployed and what is actually deployed. Every manual change is a small increment of drift.

Why it exists Infrastructure as Code makes infrastructure obey the same rules as application code: it lives in Git, it is reviewed in a PR, changes are diffable, and rebuilding from scratch is a routine operation rather than a disaster-recovery exercise. The real payoff is that rebuilding becomes boring.
