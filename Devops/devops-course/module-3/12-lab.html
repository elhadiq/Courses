Lab: containerise urlshort end to end

Goal From the repo you created in Module 1: write the app, build a multi-stage image, run the full stack with Compose, prove data survives a restart, and break/fix it deliberately.

Step 1 — files

Create app/main.py, requirements.txt, tests/test_api.py, Dockerfile (revision 3), .dockerignore and compose.yaml from the sections above. Then:

cd ~/devops/urlshort
ls -1
git add . && git commit -m "feat: urlshort app with multi-stage Dockerfile and compose"

Step 2 — build and inspect

docker build -t urlshort:0.1.0 .
docker images urlshort
# note the size. Under ~200MB is a good result.

# see the layers and what each one cost
docker history urlshort:0.1.0

Step 3 — prove the layer cache works

# touch a source file only
echo "# comment" >> app/main.py
time docker build -t urlshort:0.1.0 .
# pip install should say CACHED. Build takes ~2s, not ~60s.

# now touch dependencies
echo "" >> requirements.txt
time docker build -t urlshort:0.1.0 .
# pip install re-runs. THIS is why COPY order matters.

Step 4 — bring up the stack

docker compose up -d --build
docker compose ps
# both services should show "running"; redis should show "healthy"

curl -s localhost:8000/health
# {"status":"ok"}

curl -s -X POST localhost:8000/shorten \
  -H 'content-type: application/json' \
  -d '{"url":"https://kubernetes.io/docs/home/"}'
# {"code":"a1b2c3d","short_url":"/r/a1b2c3d"}

Step 5 — verify the redirect and the counter

CODE=$(curl -s -X POST localhost:8000/shorten -H 'content-type: application/json' \
  -d '{"url":"https://example.com"}' | grep -o '"code":"[^"]*"' | cut -d'"' -f4)
echo "code=$CODE"

curl -si "localhost:8000/r/$CODE" | head -3
# HTTP/1.1 307 Temporary Redirect ... location: https://example.com

curl -s "localhost:8000/r/$CODE" -o /dev/null
curl -s "localhost:8000/stats/$CODE"
# {"code":"...","hits":2}

Step 6 — prove the volume works

docker compose restart redis
sleep 3
curl -s "localhost:8000/stats/$CODE"
# hits are STILL there — appendonly + named volume survived the restart

# now destroy the volume and watch the data vanish
docker compose down -v
docker compose up -d
sleep 5
curl -s "localhost:8000/stats/$CODE"
# {"code":"...","hits":0}

Step 7 — break it on purpose

# point the app at localhost instead of the service name
docker compose down
REDIS_URL=redis://localhost:6379/0 docker compose up -d
docker compose logs api | tail -20
# ConnectionError: Error connecting to localhost:6379
# Because "localhost" inside the api container IS the api container.

docker compose down && docker compose up -d   # back to normal

Step 8 — run the tests inside a container

docker compose exec api sh -c "pip install pytest httpx -q && python -m pytest -q"
# 3 passed

That command is clumsy on purpose — you will replace it with a proper CI job in Module 4.

Step 9 — publish

docker tag urlshort:0.1.0 ghcr.io/<you>/urlshort:0.1.0
docker push ghcr.io/<you>/urlshort:0.1.0
git add . && git commit -m "feat: compose stack with healthchecked redis" && git push
