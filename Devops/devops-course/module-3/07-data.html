3.7 Data: volumes and why containers are ephemeral

The container's writable layer dies with the container. This is a feature: it forces you to be explicit about what is genuinely state. Anything that must survive goes in a volume.

# named volume — Docker manages the location; use this for databases
docker volume create redis-data
docker run -d --name redis -v redis-data:/data redis:7-alpine \
  redis-server --appendonly yes

# bind mount — a host path; use this for live-reloading source in dev
docker run -d -p 8000:8000 -v "$(pwd)/app:/app/app" urlshort:dev

docker volume ls
docker volume inspect redis-data
Bind mounts are a development tool They couple the container to a host path that will not exist on a server. Use them for hot-reload while coding; never in a production definition.
