4.6 Quality gates: lint, format, type, scan

Tests catch broken behaviour. These catch the rest, and — more usefully — they end style arguments in code review by making them a machine's decision.

  quality:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: "3.12" }

      - run: pip install ruff
      - name: Lint
        run: ruff check .
      - name: Format check
        run: ruff format --check .

      - name: Scan filesystem for vulnerabilities
        uses: aquasecurity/trivy-action@0.24.0
        with:
          scan-type: fs
          severity: "HIGH,CRITICAL"
          exit-code: "1"

quality and test declare no needs, so they run in parallel — you get both sets of failures in one run instead of discovering the lint error after waiting for tests.

Shift left The cost of a defect grows by roughly an order of magnitude at each stage it survives: caught by a linter in your editor (seconds), by CI (minutes), by a reviewer (hours), in production (days, plus users). Every gate you add early is buying down that multiplier.
