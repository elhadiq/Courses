Checkpoint

Job A installs dependencies; job B runs the tests and fails with "module not found". Why?
needs only orders jobs; it shares nothing. Either combine the steps into one job, or pass results explicitly via an artifact or a registry.
Why build the image once in CI and promote that same image through staging to production?
Base images move, transitive dependencies shift, timestamps change. A rebuild is a new artefact with new risk — so the thing you tested is not the thing you shipped.
Which is the most dangerous line in a workflow?
That combination runs untrusted code from any fork with your repository's secrets in scope — a full credential-exfiltration path from a single opened PR.
You should now be able to, without notes:
  • Distinguish continuous integration, delivery and deployment, and say what each demands of you.
  • Write a workflow with parallel jobs and correct needs ordering.
  • Start a service container and explain why localhost is right here but wrong in Compose.
  • Cache dependencies and Docker layers, keyed correctly.
  • Publish an image tagged with the commit SHA, and say why not latest.
  • Name three ways a pipeline leaks secrets and prevent each.
  • Make CI checks a blocking requirement on main.
  • Explain rolling vs blue/green vs canary and pick one for a given risk tolerance.
