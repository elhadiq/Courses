4.8 Secrets, and how pipelines leak them

Store secrets in Settings → Secrets and variables → Actions. Reference them as ${{ secrets.NAME }}. GitHub masks their values in logs.

- name: Deploy
  env:
    DEPLOY_KEY: ${{ secrets.DEPLOY_KEY }}
  run: ./scripts/deploy.sh
Four real leak paths
  • Echoing them. Masking is string matching. Base64-encode or split a secret and the mask misses it. Never print one, even "temporarily to debug".
  • pull_request_target on untrusted forks. That trigger runs with your secrets against a fork's code. A malicious PR can exfiltrate everything. Use plain pull_request unless you fully understand the difference.
  • Unpinned third-party actions. uses: some/action@v1 follows a mutable tag; if that repo is compromised, your next run executes attacker code with your token. For anything outside actions/ and vendors you trust, pin to a commit SHA.
  • Over-broad token permissions. Set permissions: per job at the minimum needed.
