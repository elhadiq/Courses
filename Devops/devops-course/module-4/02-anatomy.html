4.2 Anatomy of a workflow

GitHub Actions files live in .github/workflows/*.yml. The hierarchy:

  • Event — what starts it: push, pull_request, schedule, workflow_dispatch (a manual button).
  • Job — runs on a fresh virtual machine. Jobs are parallel unless you declare needs.
  • Step — either run: (a shell command) or uses: (a reusable action).
  • Runner — the VM. GitHub's hosted ubuntu-latest is free for public repos.
Every job starts on a clean machine Nothing carries over between jobs — not installed packages, not the working directory, not built files. If job B needs something job A produced, either put them in the same job or pass it through an artifact or a registry. This surprises everyone once.
