7.5 Instrumenting the application

Add to requirements.txt:

prometheus-client==0.21.0

Add to app/main.py:

import time
from fastapi import Request
from fastapi.responses import Response
from prometheus_client import (
    Counter, Histogram, Gauge, generate_latest, CONTENT_TYPE_LATEST
)

REQUESTS = Counter(
    "http_requests_total",
    "Total HTTP requests",
    ["method", "route", "status"],
)

LATENCY = Histogram(
    "http_request_duration_seconds",
    "Request latency in seconds",
    ["method", "route"],
    buckets=(0.005, 0.01, 0.025, 0.05, 0.1, 0.25, 0.5, 1.0, 2.5, 5.0),
)

LINKS = Gauge("urlshort_links_stored", "Number of short links in redis")

@app.middleware("http")
async def observe(request: Request, call_next):
    start = time.perf_counter()
    response = await call_next(request)
    elapsed = time.perf_counter() - start

    # IMPORTANT: the templated route, not the concrete path.
    # "/r/{code}" is one series; "/r/abc1234" would be one series PER LINK.
    route = request.scope.get("route")
    route_label = getattr(route, "path", "unmatched")

    REQUESTS.labels(request.method, route_label, response.status_code).inc()
    LATENCY.labels(request.method, route_label).observe(elapsed)
    return response

curl -s localhost:8000/metrics | grep http_requests_total
# http_requests_total{method="GET",route="/health",status="200"} 4.0
The LINKS gauge above is a teaching example, not production code KEYS * scans the entire Redis keyspace and blocks the server — fine with 50 keys, catastrophic with 50 million. In production use a counter incremented on write, or Redis's own dbsize. Cheap-looking instrumentation that degrades under load is a classic own goal.
