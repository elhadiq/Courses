7.3 How Prometheus works

Prometheus pulls. It periodically scrapes an HTTP endpoint — conventionally /metrics — on each target and stores the numbers as a time series. It does not receive pushes (except via a gateway for batch jobs).

Why pull is a deliberate choice: Prometheus always knows whether a target is reachable (a failed scrape is itself a signal), targets need no configuration about where to send data, and you can curl /metrics by hand to debug — which you will do constantly.

A time series is a metric name plus labels:

http_requests_total{method="POST", path="/shorten", status="200"}  1547
Cardinality will kill your Prometheus Each unique label combination is a separate series stored in memory. A label like user_id or url creates one series per distinct value — millions of them, and the server falls over. Never put unbounded values in labels: no IDs, no emails, no raw paths, no timestamps. Use /r/{code} as a templated route label, not the actual code.
