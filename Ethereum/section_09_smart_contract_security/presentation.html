Why it is high stakesContext

  • Code is immutable and handles real money.
  • External calls are where attackers strike.
  • The 2016 DAO hack drained ~15% of all ether — and forced the ETH/ETC fork.
A single ordering mistake can drain a whole contract in one transaction.
2 / 7

ReentrancyThe attack

withdraw(): 1. check balance 2. SEND ether ← triggers attacker fallback 3. set balance = 0 (too late!)

The fallback calls withdraw() again before step 3 — balance still looks full, so it pays out again and again.

Root cause: interacting with the outside world before updating your own state.
3 / 7

Read-only reentrancySubtle

Even a view function can be dangerous: another protocol (B) trusts data from A while A's state is momentarily stale.

Developers rarely guard view functions — that is the trap.

Recap

Reentrancy exploits the gap between sending ether and updating state, as in the 2016 DAO hack. The checks-effects-interactions pattern — validate, update state, then call out — plus reentrancy locks are the core defenses. Every antipattern has a matching preventative technique.
