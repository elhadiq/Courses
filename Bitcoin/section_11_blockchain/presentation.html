Mastering Bitcoin · Section 11 — blocks chained so tampering breaks everything after

1 / 8

A block = header + transactionsStructure

An 80-byte header holds the version, previous block hash, merkle root, timestamp, difficulty target and nonce; then the list of transactions.

2 / 8

Each block points backChain

Every header includes the previous block's hash. Change one byte in history and its hash changes, breaking the next block's link — and every block after it.

3 / 8

The block idIdentifier

block_id = SHA256(SHA256(80-byte header))
Bitcoin displays hashes in reversed byte order, so real block ids start with zeros on the left.
4 / 8

Merkle treesMerkle

Pair transaction hashes, hash each pair, repeat up to one merkle root. If a level is odd, the last hash is duplicated. Change any transaction and the root changes.

5 / 8

Merkle proofs (why SPV works)Proofs

To prove a transaction is in a block, send only the sibling hashes on its path to the root — about log₂(n) hashes, not all n.
