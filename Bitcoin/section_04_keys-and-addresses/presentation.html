A key is a very big secret numberConcept

A Bitcoin private key is just an enormous random number (up to ~1077). Whoever knows it controls the coins.

No username, no password reset, no recovery. The number is the money. Leak it and it is stolen; lose it and it is gone.

Why keys come in pairsKey pairs

From the private key we compute a public key. This is asymmetric cryptography: the private key signs, the public key verifies — but you cannot work backwards.

The link lives on an elliptic curve (secp256k1): K = k × G is easy; reversing it is infeasible.

Compressed public keysCompression

A public key is a point (x, y). Since y is determined by x up to a sign, wallets store x plus a one-byte parity flag: 33 bytes total.

FormSizeLayout
Uncompressed65 B0x04 + x + y
Compressed, y even33 B0x02 + x
Compressed, y odd33 B0x03 + x

From public key to addressAddresses

You share an address, not the public key. For a legacy address:

  1. HASH160 = RIPEMD160(SHA256(pubkey)) — a 20-byte fingerprint.
  2. Add a version byte.
  3. Append a 4-byte checksum and Base58-encode.
5 / 8

Base58 and Base58CheckEncoding

Base58 drops confusing characters (0/O, l/I, +, /). Base58Check adds a 4-byte checksum so a mistyped address is rejected before any coins move.

checksum = first 4 bytes of SHA256(SHA256(payload))

Coding exercisesPractice

  1. base58_encode(data) — encode bytes to Base58.
  2. checksum(payload) — the Base58Check double-SHA256 checksum.
  3. compress_pubkey(x, y) — serialize a compressed key.
