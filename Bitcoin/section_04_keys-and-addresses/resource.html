Keys and Addresses

Owning bitcoin means owning a secret number. This section explains keys, why they come in pairs, how a public key becomes the address you share, and the encoding that keeps you from losing money to a typo.

What you will be able to do

  • Say why deriving the public key from the private key is a one-way street.
  • Describe compressed public keys and their prefix bytes.
  • Trace the pipeline from public key to address.
  • Encode data in Base58 and protect it with a Base58Check checksum.

1. The one idea: a key is a very big secret number

In Section 2 we said coins are locked outputs. What actually locks them is a key. A Bitcoin private key is nothing more than an enormous randomly chosen number — a value between 1 and roughly 1077. Whoever knows that number controls the coins. There is no username, no password reset, no company that can recover it. The number is the money.

Consequence. If someone learns your private key, they can spend your coins. If you lose it, the coins are gone forever. Everything about wallets (Section 5) and security (Section 13) exists to manage this one number safely.

2. Why keys come in pairs

From the private key we compute a matching public key. The pair has a magical property, called asymmetric cryptography: the private key can produce a signature that anyone can check using the public key — but no one can work backwards from the public key to the private key. This lets you prove ownership without revealing your secret. You sign a transaction with the private key; the network verifies it with the public key; your secret stays secret.

The computation that links them lives on a special mathematical object called an elliptic curve (Bitcoin uses one named secp256k1). You do not need the deep math, but a picture helps: the curve is a smooth shape on which you can “add” points together.

Deriving the public key means starting from a fixed point G on the curve and “adding” it to itself your-private-key times: K = k × G. Doing this is fast. Undoing it — figuring out how many times you added, i.e. recovering k from K — is so hard that all the computers on Earth could not do it in the lifetime of the universe. That asymmetry is what keeps your coins safe.

private key  —(easy: k × G)→  public key  —(hard: reverse it)→  ✗ impossible

3. Compressed public keys

A public key is a point on the curve, so it has two coordinates: x and y. But the curve's equation means that for any x there are only two possible y values (an even one and an odd one). So instead of storing both coordinates, wallets store just x plus a single byte saying whether y is even or odd. That is a compressed public key: 33 bytes total.

FormSizeLayout
Uncompressed65 bytes0x04 + x (32) + y (32)
Compressed, y even33 bytes0x02 + x (32)
Compressed, y odd33 bytes0x03 + x (32)

4. From public key to address

You do not hand out your public key directly — you hand out an address, a shorter, safer string derived from it. For a classic (“legacy”) address the recipe is:

  1. Take the public key.
  2. Hash it with SHA-256, then hash that with RIPEMD-160. The combined step is called HASH160 and gives a 20-byte fingerprint.
  3. Add a version byte in front (which network / address type).
  4. Append a 4-byte checksum and encode everything in Base58 (next part).

Hashing the key before publishing it adds a second wall of protection: even if elliptic-curve math were somehow broken in the future, an attacker would still face the hash. Modern address types (P2WPKH, P2TR) use Bech32 encoding instead of Base58, but the idea — publish a hash of the key, not the key — is the same.

5. Base58 and Base58Check

Base58 is a way of writing a big number as text. It is like the Base64 you may have seen, but with the confusing characters removed: no 0 (zero) vs O (capital o), no l (lowercase L) vs I (capital i), and no + or /. That leaves 58 clear characters, so an address is hard to mis-read or mis-type.

But “hard to mistype” is not “impossible.” So Bitcoin wraps the data in Base58Check, which appends a 4-byte checksum — the first four bytes of the double SHA-256 of the payload. If you change even one character of the address, the checksum no longer matches and any wallet refuses to send. This is why a fat-fingered address almost never results in lost money: it simply gets rejected.

Base58Check checksum, in one line

checksum = first 4 bytes of SHA256(SHA256(version + payload))
