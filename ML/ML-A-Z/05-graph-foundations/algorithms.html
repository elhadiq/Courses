How to read this annex

Each algorithm is set out the same way: what it is handed, what it must hand back, then the steps in the order you would carry them out. Nothing here assumes you can read a program — the point is the reasoning.

Finding the connected components

Traversal \(\cdot\) visits every node once

Split a graph into the pieces that are actually connected to each other.

Input and output

Given. A list of nodes and a list of edges.

Produce. A component number for every node, and the count of components.

The procedure, step by step

  1. Build the neighbour lists. For each node, the list of nodes joined to it. Add each edge to both endpoints' lists — forgetting the second direction is the classic first mistake.
  2. Mark every node unvisited. Keep a component number for each node, initially blank.
  3. Take the lowest unvisited node. Give it the next component number and put it in a waiting queue.
  4. Drain the queue. Take a node from the front of the queue; for each of its neighbours that is still blank, give it the same component number and add it to the back of the queue. Continue until the queue empties.
  5. Repeat. Go back and take the next still-blank node. When none remain, the number of component numbers issued is the answer.
Worked by hand

Six nodes, edges 0–1, 1–2 and 3–4.

Three components. This matters far beyond bookkeeping: the number of components is exactly the number of zero eigenvalues of the Laplacian, which is the fact spectral clustering rests on.

Why the answer is correct

Every node reachable from the starting node receives its number, and no node outside that set does. The queue holds exactly the nodes found but not yet expanded.

Why it stops

Each node enters the queue at most once, because it is numbered as it is added and only blank nodes are added.

What it costs

Every node and every edge is examined a constant number of times: \(O(n+m)\), which is the best possible.

Where it goes wrong
  • Adding a node to the queue without numbering it immediately lets it be added several times, and on a dense graph the queue explodes.
  • On a directed graph this finds only what is reachable, which is a different and weaker notion than a component.

Counting walks with matrix powers

Direct computation \(\cdot\) the key structural fact

Count how many ways one can walk from each node to each other node in exactly \(k\) steps.

Input and output

Given. The adjacency table of the graph and a length \(k\).

Produce. A table whose entry in row \(u\), column \(v\) is the number of walks of length \(k\) from \(utov\).

The procedure, step by step

  1. Write down the adjacency table. One row and column per node; a 1 where an edge exists, 0 elsewhere. For an undirected graph this table is symmetric.
  2. Understand what one step means. The table itself already answers the question for \(k = 1\): there is one walk of length 1 from \(utov\) exactly when they are joined.
  3. Combine two step-counts. To count walks of length \(k+1\) from \(utov\), go over every possible node \(z\) in the middle: the number of ways to reach \(zink\) steps, times the number of ways to go from \(ztov\) in one. Add these up.
  4. Repeat to the length you need. Each combination advances the walk length by one.
  5. Read the diagonal for closed walks. The entry in row \(u\), column \(u\) counts walks that return to where they started. At length three, the total down the diagonal is six times the number of triangles — each triangle counted once per starting node and once per direction.
Worked by hand

A triangle on three nodes.

LengthRow 0 of the tableMeaning
10, 1, 1one step reaches each neighbour

32, 3, 3diagonal total is 6 = \(6 \times 1\) triangle

This is the fact that makes everything later work: multiplying by the adjacency table is one hop of propagation. Doing it repeatedly is what a random walk does, and what each layer of a graph network does.

Why the answer is correct

Proved by induction. It holds for one step by definition, and the combination step enumerates every walk of length \(k+1\) exactly once, by its unique node at position \(k\).

Why it stops

\(k\) combinations, fixed in advance.

What it costs

Each combination is cubic in the number of nodes if done densely. Real graphs are sparse, so in practice one never forms these tables — one multiplies a single vector by the adjacency structure, at cost \(O(m)\) per step.

Where it goes wrong
  • A walk may revisit nodes and edges. It is not a path. The counts grow very quickly and overflow ordinary integers for moderate \(k\).
  • For large \(k\) the entries become dominated by the principal direction of the graph and stop distinguishing nodes — the same phenomenon that limits how deep a graph network can usefully be.

Building the Laplacian and measuring smoothness

Direct computation \(\cdot\) the central object

Build the matrix that measures how much a quantity spread over the nodes disagrees across edges.

Input and output

Given. The graph, and optionally a value attached to each node.

Produce. The Laplacian table, and the smoothness number of the given values.

The procedure, step by step

  1. Count the degrees. For each node, how many edges touch it.
  2. Place the degrees on the diagonal. Start from a table of zeros and write each node's degree in its own diagonal position.
  3. Subtract the adjacency. Put −1 in every position corresponding to an edge, both ways round.
  4. Check the row sums. Every row must now add to zero. This is the arithmetic statement that a constant value over all nodes has no disagreement anywhere, and it is worth verifying because it catches most construction errors immediately.
  5. Measure the smoothness of a set of values. Do not use the table for this. Go over the edges directly: for each edge, square the difference between the values at its two ends, and add up. That sum is exactly the quantity the Laplacian computes, obtained in time proportional to the number of edges rather than its square.
Worked by hand

A path 0–1–2 with values attached to the nodes.

Any constant assignment scores zero, whatever the constant. That is why the constant direction is the one associated with the smallest possible smoothness value, and why the second smallest is the interesting one.

Why the answer is correct

The smoothness number is a sum of squares, so it is never negative, and it is zero exactly when the values are constant on each connected piece of the graph.

Why it stops

Direct.

What it costs

\(O(m)\) for the smoothness number; \(O(n^2)\) memory if you insist on building the full table, which for a real graph you should not.

Where it goes wrong
  • On graphs where some nodes have far more edges than others, the high-degree nodes dominate the smoothness number. Dividing through by degree gives the normalised variants used in the next section.
  • Forgetting to place both −1 entries breaks the symmetry and every conclusion that follows.

Label propagation

Iterative method \(\cdot\) needs no training at all

Spread known labels from a few nodes to all the others along the edges.

Input and output

Given. A graph, and labels for a small subset of nodes.

Produce. A value for every unlabelled node.

The procedure, step by step

  1. Fix the known values. The labelled nodes keep their labels throughout and are never updated.
  2. Start the rest anywhere. Zero will do. The starting point does not affect where this ends up.
  3. Replace each unknown by the average of its neighbours. Sweep over the unlabelled nodes, setting each to the average of the current values at the nodes joined to it.
  4. Repeat until settled. Continue until no value changes by more than a small tolerance.
  5. Read off the answer. Threshold the final values to obtain labels, or keep them as confidences.

The final values fall evenly between the two known ends. That is exactly what minimising disagreement across edges produces on a path, and it can be read off without any iteration at all — the iteration is simply a convenient way to reach it.

Why the answer is correct

At rest, every unknown equals the average of its neighbours. That is precisely the condition for the total disagreement across edges to be as small as possible given the fixed known values.

Why it stops

Each sweep moves the values closer to the resting point by a constant factor, provided every unlabelled node can reach a labelled one.

What it costs

\(O(m)\) per sweep.

Where it goes wrong
  • It assumes connected nodes share labels. On a graph where edges tend to join different classes, this actively destroys the signal. Measure that tendency before trusting it.
  • A group of unlabelled nodes with no path to any labelled node will sit at whatever they started from. Detect them and abstain.
Worth knowing

Free of parameters and of training, this is a genuinely strong baseline. Elaborate graph networks are quite often unable to beat it.
