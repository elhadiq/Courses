Building the similarity graph

Preprocessing \(\cdot\) the step that decides everything

Turn a cloud of points into a graph whose edges express closeness.

Input and output

Given. The observations and a neighbourhood size \(k\).

Produce. A graph on the observations.

The procedure, step by step

  1. Compute the distances. For each observation, its distance to every other.
  2. Keep each point's k nearest. Join each observation to its \(k\) closest neighbours. This gives a one-way relation, since being someone's nearest neighbour is not mutual.
  3. Make it symmetric. Join two observations if either chose the other. The stricter variant, joining only when both chose, gives tighter but more fragmented groups.
  4. Weight the edges if you wish. Give each edge a weight falling off with distance. Use a scale that adapts to each point — for instance its distance to its seventh neighbour — so that dense and sparse regions are treated even-handedly.
  5. Check the graph is connected. If it has fallen into pieces, the method will simply return those pieces. Raise \(k\) until it is connected.
Why the answer is correct

Only local distances are used. That is the whole point: on curved data, near distances are trustworthy and far ones are not.

Why it stops

Direct.

What it costs

Quadratic in the number of observations if done naively; a spatial index reduces this substantially in low dimensions.

Where it goes wrong
  • This is the real hyperparameter. Results are far more sensitive to how the graph is built than to anything done afterwards. A scale too large connects everything into one blob; too small shatters it into dust.
  • A single global scale fails when some regions are dense and others sparse. Use a per-point scale.

Spectral clustering

Spectral method \(\cdot\) clustering by connectivity

Divide a graph into well-connected groups, cutting as few edges as possible while keeping the groups balanced.

Input and output

Given. A similarity graph and a number of groups \(k\).

Produce. A group label for every node.

The procedure, step by step

  1. Build the Laplacian. Degrees on the diagonal, negated edges off it, as in the previous section. Divide through by degrees to obtain the normalised version, which prevents high-degree nodes from dominating.
  2. Find the directions of least disagreement. Compute the \(k\) directions along which values assigned to nodes disagree least across edges. The very first is the constant one and carries no information; the interesting ones are those immediately after it.
  3. Give each node new coordinates. Stack those \(k\) directions side by side. Each node now has \(k\) numbers — its position in a new space where closeness means well-connected rather than geometrically near.
  4. Normalise the rows if using the symmetric form. Rescale each node's new coordinates to unit length, which places them on a sphere and makes the groups easier to separate.
  5. Run ordinary clustering in the new space. Apply the alternating method of Section 4 to these new coordinates.
  6. Carry the labels back. Each node's group in the new space is its group in the original data.
Worked by hand

Why the last step is not circular. The same data, judged two ways:

SpaceAre two crescents separable by a straight boundary?
original coordinatesno — ordinary clustering fails
spectral coordinatesyes — they become two compact blobs

Ordinary clustering failed because of the geometry, not because the method was wrong. Once the coordinates are changed so that connectivity becomes distance, it is exactly the right tool.

Why the answer is correct

Splitting a graph into balanced, weakly connected pieces is computationally intractable. Dropping the requirement that the answer be a clean yes/no per node turns it into finding these directions, which is a standard computation. The relaxation provably costs at most a squared factor, so the answer cannot be arbitrarily bad.

Why it stops

Direct computation followed by the alternating method.

What it costs

Cubic in the number of nodes for a full decomposition. Only \(k\) directions are actually needed, so iterative solvers on the sparse graph are used instead in practice.

Where it goes wrong
  • Nothing can be added afterwards: a new observation has no coordinates without redoing the computation. This is what makes the method unsuitable for data that keeps arriving.
  • It quietly prefers groups of comparable size, because of how the balance is enforced.

The sweep cut

Rounding \(\cdot\) turns numbers into a decision

Convert the continuous values produced by the previous method into an actual split of the graph, and do so with a guarantee.

Input and output

Given. The graph and one value per node — the direction of least disagreement after the constant one.

Produce. A split of the nodes into two groups.

The procedure, step by step

  1. Sort the nodes by their value. Lowest first. The ordering is what matters, not the values.
  2. Consider every prefix. Take the first node alone, then the first two, then the first three, and so on. Each prefix is a candidate group.
  3. Score each candidate. Count the edges leaving the candidate group, divided by the smaller of the two sides' total degree. Low is good: few edges cut, and neither side trivially small.
  4. Keep the best prefix. The candidate with the lowest score is the answer.
  5. Do not simply split at zero. Splitting at value zero is quicker and often close, but the sweep is what carries the guarantee.

Why the answer is correct

The best prefix in this ordering is provably within a square-root factor of the best split of the entire graph — a guarantee that no amount of arbitrary thresholding would give.

Why it stops

\(n-1\) candidates.

What it costs

One sort, then one pass maintaining the counts incrementally.

Where it goes wrong
  • Recomputing the cut from scratch for every prefix makes this needlessly slow. Update the counts as each node moves across.

Choosing the number of clusters by the eigengap

Model selection \(\cdot\) reads the spectrum

Decide how many groups the data actually contain.

Input and output

Given. The disagreement values, sorted from smallest.

Produce. A number of groups.

The procedure, step by step

  1. Recall the ideal case. If the graph fell into \(k\) genuinely separate pieces, exactly \(k\) of these values would be zero and the next would be clearly positive.
  2. Accept that real graphs are perturbed. Weak connections between groups lift the zeros slightly, but they stay small.
  3. List the gaps. Take the differences between consecutive values.
  4. Choose the largest gap. The number of values before the biggest jump is the number of groups.
  5. Be willing to conclude nothing. If no gap stands out, the graph has no clear group structure. That is a legitimate finding, not a failure.
Worked by hand

Twelve nodes forming three triangles, with bridges added between them.

The method degrades honestly: as the groups genuinely merge, the gap disappears rather than producing a confident wrong answer.

Why the answer is correct

Rests on the fact that the number of zero values equals the number of separate pieces, together with the principle that a small change to the graph makes only a small change to these values.

Why it stops

Direct.

What it costs

Negligible once the values are known.

Where it goes wrong
  • On graphs with groups at several scales there are several gaps and the choice is genuinely ambiguous.
  • Always inspect the values themselves rather than trusting the automatic choice.
