Ordinary least squares by the normal equations

Direct method \(\cdot\) exact solution in one shot

Fit a straight line (or a hyperplane) through a cloud of points so that the total squared vertical distance to the line is as small as possible.

Input and output

Given. A table of \(n\) observations. Each row has \(d\) input numbers and one output number.

Produce. The \(d+1\) coefficients of the fitted function: one intercept and one slope per input.

The procedure, step by step

  1. Add a column of ones. Put a column of 1s at the front of the input table. This is a bookkeeping trick: the intercept then behaves like any other coefficient and needs no special treatment.
  2. Form the square summary matrix. For every pair of columns, multiply them entry by entry and add up. This gives a small square table with one row and column per input — the matrix \(X^{T}X\). Its size does not depend on how many observations you have, only on how many inputs.
  3. Form the right-hand side. For every input column, multiply it entry by entry with the output column and add up. This gives one number per input — the vector \(X^{T}y\).
  4. Solve the small linear system. Solve \(X^{T}X\,\theta = X^{T}y\) for \(\theta\). This is an ordinary system of \(d+1\) equations in \(d+1\) unknowns, solved by elimination. Do not compute the inverse matrix and multiply — solving directly is faster and far more accurate numerically.
  5. Read off the answer. The first coefficient is the intercept, the rest are the slopes.

With \(n=4\), the two normal equations are \(4\theta_0 + 10\theta_1 = 20\) and \(10\theta_0 + 30\theta_1 = 61\). Eliminating gives \(\theta_1 = 2.1\) and \(\theta_0 = -0.25\), so the fitted line is \(y = 2.1x - 0.25\).

Why the answer is correct

The fitted values are the orthogonal projection of the outputs onto the space of things the inputs can express. Because the projection is orthogonal, the leftover errors are at right angles to every input column: no input carries any unused information. That is exactly the condition the normal equations state, so any solution of them is a minimiser, and the objective being convex means there is no other.

Why it stops

There is no loop to worry about. Elimination on a system of \(d+1\) equations finishes after a fixed number of steps.

What it costs

Building the summary matrix dominates: about \(n(d+1)^2\) multiplications, then roughly \((d+1)^3/3\) to solve. Linear in the number of observations, cubic in the number of inputs — so it is the width of the table, not its length, that hurts.

Where it goes wrong
  • If two inputs are exact copies of one another, or one is a sum of others, the summary matrix cannot be solved — infinitely many coefficient sets fit equally well. Drop the redundant column, or use the ridge variant below.
  • If two inputs are almost redundant, the solution still exists but swings wildly with tiny changes in the data. Watch for huge coefficients of opposite sign.
  • One far-away point can drag the whole line towards it, because the cost grows with the square of the error.

Batch gradient descent

Iterative method \(\cdot\) approaches the answer gradually

Reach the same best-fitting coefficients without ever building or solving a matrix system, by repeatedly nudging the coefficients downhill.

Input and output

Given. The same table, a starting guess for the coefficients (all zeros will do), a step size \(\eta\), and a number of rounds.

Produce. Coefficients that are close to the best-fitting ones — closer the more rounds you run.

The procedure, step by step

  1. Predict with the current coefficients. For every observation, combine its inputs with the current coefficients to get a predicted output.
  2. Measure the leftovers. Subtract each prediction from the true output. A positive leftover means the prediction was too low.
  3. Ask each coefficient how it contributed. For each input column, multiply the leftovers by that column entry by entry and average. A large positive value means increasing this coefficient would reduce the error.
  4. Take a step. Move each coefficient a little in the direction that reduces the error, the size of the move being \(\eta\) times the quantity just computed.
  5. Repeat. Go back to the first step. Stop when the coefficients barely move, or after the agreed number of rounds.

Each round closes half the remaining gap. The distance to the answer is multiplied by the same factor every time — that is what geometric convergence looks like in a table.

Why the answer is correct

Provided the step is not too large, every round leaves the total error no larger than before. The error surface for this problem is a bowl with a single lowest point, so a sequence that never goes uphill and never stalls can only be heading for that point.

Why it stops

It does not stop by itself. You stop it — after a fixed number of rounds, or once the change in the coefficients falls below a threshold you choose.

What it costs

One pass over the whole table per round: about \(nd\) multiplications. Cheap per round, but you need many rounds. Attractive exactly when \(d\) is too large for the direct method.

Where it goes wrong
  • Too large a step and the coefficients oscillate and then blow up. The safe ceiling is governed by the largest curvature of the bowl.
  • Too small a step and it crawls; you may stop while still far away and mistake that for the answer.
  • If one input ranges over thousands and another over fractions, the bowl becomes a long narrow valley and progress is painfully slow. Rescale every input to a comparable range first.
Worth knowing

Using one randomly chosen observation per round instead of all of them gives the stochastic variant. Each step is then noisy but \(n\) times cheaper, which is the only practical option on very large tables.

K-fold cross-validation

Evaluation procedure \(\cdot\) wraps around any method

Estimate honestly how well a fitted model will do on data it has never seen, using only the data you already have.

Input and output

Given. The full dataset, a number of folds \(K\) (5 or 10 in practice), and a fitting method to assess.

Produce. One error estimate, together with a spread that tells you how much to trust it.

The procedure, step by step

  1. Shuffle, then deal into K piles. Shuffle the observations once, then deal them out into \(K\) piles of roughly equal size, like dealing cards.
  2. Hold out one pile. Set pile number one aside. It is now untouchable.
  3. Fit on the rest. Fit the model using only the other \(K-1\) piles. Every choice the method makes — including any preprocessing that learns from data — must be made from these piles alone.
  4. Score on the held-out pile. Predict the observations in the pile you set aside and record the error. These predictions are honest, because nothing about that pile influenced the fit.
  5. Rotate. Put the pile back, set aside the next one, and repeat until every pile has been the held-out one exactly once.
  6. Combine. Average the \(K\) recorded errors. Report the spread alongside the average — an average of 0.30 with a spread of 0.02 means something quite different from the same average with a spread of 0.15.
Worked by hand

Six observations, three folds. Dealing in turn puts observation 1 in fold A, 2 in B, 3 in C, 4 in A, and so on.

Every observation is predicted exactly once by a model that never saw it, so all six contribute to the estimate without any of them being scored by a model that had already met them.

Why the answer is correct

Each prediction is made by a model fitted without that observation. The estimate is therefore of the error on genuinely new data, not of the error the model makes on what it memorised.

Why it stops

Exactly \(K\) rounds, decided before you start.

What it costs

\(K\) complete fits. That is the whole price, and it is why \(K = n\) (holding out one observation at a time) is rarely worth it.

Where it goes wrong
  • The classic mistake: standardising, selecting features, or imputing missing values on the whole dataset before splitting. Information from the held-out pile then leaks into the fit and the estimate comes out flattering. Every such step belongs inside the loop.
  • With grouped data — several readings from the same patient, several sentences from the same document — deal whole groups into piles, never individual rows.
  • With ordered data, dealing at random lets the model learn from the future to predict the past. Split by time instead.

Ridge regression

Direct method \(\cdot\) least squares with a brake

Fit the same kind of function, but discourage large coefficients so the answer is stable when inputs are nearly redundant.

Input and output

Given. The same table, plus a penalty strength \(\lambda \gt 0\).

Produce. Coefficients that fit slightly less well but move far less when the data are perturbed.

The procedure, step by step

  1. Standardise the inputs. Rescale every input column to have average 0 and spread 1. This matters here in a way it did not before: the penalty treats all coefficients alike, so they must be on comparable scales or the penalty is arbitrary.
  2. Build the same summary matrix. Exactly as for ordinary least squares.
  3. Add the penalty to the diagonal. Add \(\lambda\) to each entry running down the main diagonal, and to that diagonal only. Do not penalise the intercept.
  4. Solve. Solve the resulting system as before.
  5. Choose the penalty by cross-validation. Repeat the whole thing for a range of \(\lambda\) spaced by factors of ten, score each by cross-validation, and keep the best.
Worked by hand

Two inputs that are nearly identical, so ordinary least squares is unstable. Watch what the penalty does to the coefficients.

The two coefficients start out enormous and opposed, nearly cancelling. The penalty pulls them together without changing their sum, which is the part the data actually determine.

Why the answer is correct

Adding a positive number to the diagonal makes the system solvable even when the original one was not, and the solution it produces is the unique minimiser of the fitting error plus the penalty.

Why it stops

Direct, like ordinary least squares.

What it costs

The same as ordinary least squares, plus one full repeat per candidate penalty value.

Where it goes wrong
  • Forgetting to standardise makes the penalty fall unevenly and the result meaningless.
  • Penalising the intercept shrinks the overall level of the predictions towards zero, which is almost never what you want.
  • Choosing \(\lambda\) by looking at the fitting error picks zero every time. It must be chosen on held-out data.
Worth knowing

Penalising the sum of absolute values instead of squares gives the lasso, which drives some coefficients to exactly zero and so selects inputs. That variant has no closed form and needs an iterative solver.
